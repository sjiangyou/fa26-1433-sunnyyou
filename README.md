# Research project title

What is the impact of strengthening hurricanes on home and flood insurance prices in hurricane and flood prone areas?

## Reproducing the project

The complete currently implemented workflow is:

```bash
make all
```

This checks that Python and R are available, creates or updates the project-local
R `renv` environment with the required packages, downloads all configured raw
data, creates the derived analysis panels, and estimates the annual flood
event-study models and figures. The first R setup requires internet access so
that `renv` can install the packages; the resolved versions are recorded in
`renv.lock` after the first successful setup. The lockfile is intentionally
generated by `renv` so it captures the versions available in the installation
environment.

Individual stages are available through `make help`. In particular,
`make download-raw` downloads the configured raw-data sources, `make derive`
creates the analysis panels, and `make estimate-model` estimates the annual
event-study models. `make estimate-model-no-2021` estimates the transition-year
robustness specification. `make plot-figures` creates the Gallagher-style PNG
figures. `make all` runs every currently implemented stage in
dependency order. Data manipulation and plotting will use R; model training
and evaluation will use Python as those stages are added.

The model stage writes these reproducible artifacts to `data/derived/model/`:

- `annual_event_study_panel.csv`: annual county observations for all available states and territories used for estimation;
- `event_study_coefficients.csv`: baseline event-time coefficients and the
  post-minus-pre interaction coefficients, with the latter marked as the
  coefficients of interest;
- `event_study_effects.csv`: pre responses, post responses, and post-minus-pre
  differences with standard errors and confidence intervals;
- `event_study_coefficients_translated.csv`: coefficient estimates with implied
  percentage changes calculated as `100 * (exp(estimate) - 1)`;
- `event_study_effects_translated.csv`: the complete effects table with point
  estimates and confidence intervals translated to percentage changes;
- `event_study_fit_statistics.csv`: observation counts and model fit statistics.

The transition-year robustness stage writes matching artifacts with
`_no_2021.csv` suffixes. It removes calendar-year 2021 observations only after
constructing event-time regressors from every flood year. A flood occurring in
2021 can therefore still affect retained lead and lag observations, and it
remains classified as a pre-transition flood cohort under the main definition.

The plotting stage reads `event_study_effects_translated.csv` and writes three
ggplot2 PNG figures to `output/`: direct-flood responses, nonflooded-neighbor
responses, and post-minus-pre response differences. The omitted event year -1
is shown as a normalized zero, and estimated points include county-clustered
95 percent confidence intervals.

The annual model follows Gallagher's adjacent-nonflooded-county treatment
definition. A county-year is a geographic neighbor event only if at least one
border-adjacent county floods and the focal county does not flood. The saved
annual panel retains the raw `adjacent_flood` indicator so this exclusion can
be audited directly. The estimator constructs a one-row-per-FIPS county lookup
and stops unless the balanced panel contains exactly one observation per
county-year.

The raw-data acquisition script uses FEMA's public OpenFEMA endpoints:

```bash
python code/download_fema_nfip_data.py
```

This downloads the FEMA disaster-declaration and current v3 redacted NFIP-claims
files into `data/raw/`, and skips the existing NFIP policy extract. The policy file
is approximately 30 GB, so the raw data are excluded from Git. See
[`data/raw/SOURCES.md`](data/raw/SOURCES.md) for source links, file contents,
and retrieval notes. The acquisition command must be run in an environment
with internet access.

## Repository structure

| Directory | Purpose |
|---|---|
| `code/` | Scripts used to acquire, clean, analyze, and visualize data |
| `data/raw/` | Original source data; ignored by Git unless explicitly allowed |
| `data/derived/` | Data created by the project's code; ignored by Git unless explicitly allowed |
| `output/` | Generated figures, tables, and other results |
| `paper/` | Paper source files and rendered drafts |

## Data status

The repository currently contains the redacted NFIP policy extract at
`data/raw/FimaNfipPoliciesV2.csv`. Disaster declarations and NFIP claims can
be retrieved with the acquisition script above. These sources cover NFIP
policies and claims, not private flood insurance, and the records are redacted
for analysis at geographic rather than named-household level.

## Working practices

- Keep the `main` branch in a usable state.
- Use GitHub issues to record consequential tasks, questions, and decisions.
- Use short-lived branches to test important alternatives, then record the conclusion in the related issue.
- Commit small, coherent changes with descriptive messages.
- Never commit passwords, API keys, restricted data, or personally identifiable information.
- Update this README whenever the reproduction steps or directory structure change.
